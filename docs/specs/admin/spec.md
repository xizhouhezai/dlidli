## 1. 背景与用户故事

UGC 平台合规底线："先审后播"。管理后台是内部效率工具，覆盖内容审核、用户治理、运营配置、数据大盘、权限与系统管理五大职能，需完整的 RBAC 权限体系与操作审计。

- 作为 **审核员**，我可以在审核队列中查看机审标记的风险点并做出通过/驳回决定，以便高效完成先审后播。
- 作为 **运营**，我可以配置分区/Banner/热搜与查看数据大盘，以便进行内容运营。
- 作为 **管理员**，我可以管理后台账号、角色与权限点，以便安全地分权协作。

## 5. 权限与账号体系（RBAC）

采用标准 **RBAC**（用户-角色-权限三层）：管理员账号绑定一到多个角色，角色聚合权限点，权限点控制菜单可见性与操作按钮。超级管理员拥有全部权限且可管理角色/权限。

### 5.1 权限管理（PERM）

权限点分两类，统一以 `模块:操作` 命名、按 code 校验：

- **页面权限（menu）**：控制左侧菜单/路由页面的可见与可访问；
- **按钮权限（button）**：控制页面内操作按钮/动作的可用，挂在所属页面权限下。

| ID | 需求 | 验收标准（EARS） | 优先级 |
| --- | --- | --- | --- |
| PERM-01 | 权限点树 | **THE SYSTEM SHALL** 按「页面权限（menu）→ 按钮权限（button）」两级树形展示与维护 | P1 |
| PERM-02 | 权限点新增 | **WHEN** 新增权限点 **THE SYSTEM SHALL** 校验 code 唯一、button 必挂合法 menu | P1 |
| PERM-03 | 权限点编辑 | **THE SYSTEM SHALL** 支持修改名称/路径/图标/排序/挂载父级；code 建议锁定（改 code 影响鉴权） | P1 |
| PERM-04 | 权限点删除 | **IF** 权限点有角色引用或有子节点 **THEN THE SYSTEM SHALL** 禁删（同步清理角色关联） | P1 |
| PERM-05 | 后端鉴权中间件 | **THE SYSTEM SHALL** 按令牌解析角色→权限集合，接口按所需 code 校验（super 短路放行） | P0 |
| PERM-06 | 前端权限指令 | **THE SYSTEM SHALL** 提供 `v-perm` 指令控制按钮显隐，菜单按权限过滤 | P0 |

> **权限治理规范（强制）**：后续**新增任何管理后台功能都必须同步登记权限点**——新增页面登记一个页面权限（menu），页面内每个受控操作登记按钮权限（button，挂到该页面 menu 下），并按需分配到相应内置角色。权限点是新功能的验收项之一，缺失视为未完成。

### 5.4 预设角色与权限矩阵

| 角色 | code | 权限范围 |
| --- | --- | --- |
| 超级管理员 | `super` | 全部 + 账号/角色/权限管理 |
| 审核主管 | `review_lead` | 审核 + 复审 + 审核数据 + 敏感词库 |
| 审核员 | `reviewer` | 认领队列审核 |
| 运营 | `operator` | 运营配置（分区/Banner/热搜/公告）+ 数据大盘只读 |
| 用户治理 | `moderator` | 用户查询/处罚/申诉复核 |
| 数据分析 | `analyst` | 数据大盘只读 |

> 内置角色随系统初始化创建；`super` 不可编辑权限（恒为全集）、不可删除。

### 5.5 安全与审计

- 所有写操作二次确认 + 审计日志（操作者/时间/对象/动作/前后值/IP）。
- 后台独立域名 + IP 白名单 + 强制 2FA（V1）。
- 令牌与 C 端完全隔离（jwtx Admin claim），停用账号即时失效。

## 7. 边界与异常

- **IF** 内置角色被删除/权限被编辑 **THEN THE SYSTEM SHALL** 拒绝（内置角色禁删/权限锁定；super 恒为全集）。
- **IF** 管理员停用/删除自己 **THEN THE SYSTEM SHALL** 拒绝。
