# 总体架构

> 状态：草案 ｜ 更新日期：2026-07-28

## 1. 架构原则

1. **单体起步，微服务演进**：MVP 用 Go 模块化单体（Modular Monolith）快速迭代，按领域划分包边界，为 V2 拆分微服务预留接缝。
2. **读写分离 + 缓存优先**：视频社区读写比 > 100:1，热点数据全部走 Redis。
3. **异步解耦**：转码、审核、通知、计数、索引同步全部走消息队列。
4. **多端一套 API**：REST API 网关统一服务 Web/H5/小程序/App。

## 3. 服务演进路线

| 阶段 | 形态 | 说明 |
| --- | --- | --- |
| MVP | 单体 `dlidli-api` + 转码 Worker + 管理后台 | 三个可部署单元，模块内分层 |
| V1 | + `dlidli-comet`（WS 网关）+ 通知/审核 Worker | 实时能力独立 |
| V2 | 拆出：用户服务、视频服务、互动服务、搜索推荐服务 | gRPC 内部通信，按压力优先拆互动/计数 |
| V3 | + 支付服务、直播服务（推流/房间/礼物） | 强一致域独立部署 |

## 4. 技术选型清单

| 类别 | 选型 | 说明 |
| --- | --- | --- |
| 后端语言 | Go 1.24+ | 高并发、部署简单 |
| Web 框架 | Gin | 生态成熟；V2 微服务化引入 gRPC + Kratos 评估 |
| ORM | GORM | 配合 SQL 审查规范 |
| 数据库 | MySQL 8.0 主从 | 业务主存储 |
| 缓存 | Redis 7（哨兵→集群） | 会话、计数、Feed 收件箱、弹幕段缓存 |
| 消息队列 | Kafka | 转码任务、事件总线、索引同步 |
| 对象存储 | MinIO（自建起步）→ 云 OSS | 源片、HLS 切片、图片 |
| 搜索 | Elasticsearch 8 + IK | V1 引入 |
| OLAP | ClickHouse | V2 引入（播放日志、数据看板） |
| 视频处理 | FFmpeg | 转码/抽帧/截图 |
| 网关 | Nginx（MVP）→ APISIX | 路由、限流、TLS |
| 服务发现/配置 | etcd + 配置中心（V2） | 微服务阶段引入 |
| 可观测 | Prometheus + Grafana + Loki + OTel | 指标/日志/链路 |
| 部署 | Docker Compose（MVP）→ Kubernetes（V2） | CI/CD：GitHub Actions |

## 5. 关键横切设计

- **统一响应**：`{ code, message, data, trace_id }`；错误码分段（1xxxx 通用 / 2xxxx 账号 / 3xxxx 视频 …）。
- **认证**：网关校验 JWT → 透传 `X-User-Id`；内部服务互信（V2 加 mTLS）。
- **幂等**：写接口支持 `Idempotency-Key`；消息消费者按业务键去重。
- **多环境**：dev / test / staging / prod 四套，配置与代码分离。
