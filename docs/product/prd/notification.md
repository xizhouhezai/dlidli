# PRD：消息通知

> 优先级：`P1` ｜ 版本：V1（通知）/ V2（私信） ｜ 状态：草案

## 1. 需求背景

互动闭环需要"被回应感"：评论被回复、视频被点赞都应及时触达；私信满足用户间、商务合作沟通需求。

## 2. 功能需求

### 2.1 通知中心（V1）

| 编号 | 功能 | 说明 | 优先级 |
| --- | --- | --- | --- |
| MSG-01 | 回复我的 | 评论回复、弹幕回复聚合；点击跳转原文定位 | P1 |
| MSG-02 | @ 我的 | 评论/动态中被 @ | P1 |
| MSG-03 | 收到的赞 | 点赞聚合（"xxx 等 N 人赞了你的评论"），按内容聚合防刷屏 | P1 |
| MSG-04 | 系统通知 | 审核结果、违规处罚、活动公告、等级提升 | P1 |
| MSG-05 | 未读红点 | 分类未读数（上限 99+），已读即消；全部标记已读 | P1 |
| MSG-06 | 通知设置 | 按类型开关（如关闭"收到的赞"提醒） | P2 |

### 2.2 私信（V2）

| 编号 | 功能 | 说明 | 优先级 |
| --- | --- | --- | --- |
| MSG-10 | 一对一私信 | 文字（≤500 字）、图片；会话列表按最新消息排序 | P1（V2） |
| MSG-11 | 发送限制 | 未互关每天最多给同一人发 1 条（防骚扰）；互关不限 | P1（V2） |
| MSG-12 | 消息治理 | 拉黑即不可发送；举报会话；机审过滤 | P1（V2） |
| MSG-13 | 在线推送 | 在线时 WebSocket 实时；离线进未读 | P1（V2） |

### 2.3 推送（App/V3）

- App 离线推送（厂商通道），推送频控每日 ≤ 3 条运营推送。
- 关注 UP 主更新推送（特别关注实时，普通关注每日聚合）。

## 3. 技术要点

- 通知采用写扩散（点对点事件）+ 聚合策略（赞类合并）。
- 存储：MySQL 通知表（按接收者分表预留）+ Redis 未读计数。
- 事件源：互动/审核/系统事件通过消息队列异步生成通知。

## 4. 指标

- 通知生成延迟 < 5s；未读计数准确率 100%。
- 通知点击率 ≥ 20%（回复我的类目标 ≥ 50%）。
