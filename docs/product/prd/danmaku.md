## 1. 需求背景

弹幕是产品差异化核心，营造"一起看"的陪伴感。需兼顾表达自由与观看体验（防遮挡、防刷屏）。进阶目标：在 MVP 基础弹幕之上，补齐 B 站用户习以为常的**样式选择、列表面板、屏蔽治理、实时下发**四大能力。

## 3. 关键交互

- 弹幕输入框固定于播放器下方；发送后本地立即上屏（乐观展示）。
- **输入框工具条**（B 站式）：模式选择（滚动/顶部/底部）+ 颜色色板（8 预设色；非白色与顶/底模式 Lv3 解锁，低等级置灰并提示）。
- **弹幕列表面板**（独立弹窗）：播放器右上角入口；列表按时间排序，点击跳转；每条支持复制 / 举报 / 屏蔽发送者。
- **悬停弹幕**：滚动暂停；操作：复制 / 举报 / 屏蔽发送者。
- **弹幕设置面板**：播放器"弹幕"开关旁齿轮入口；不透明度 / 字号缩放 / 显示区域 / 速度 / 密度。
- **屏蔽管理**：设置页（或成长中心）"弹幕屏蔽"：关键词增删（≤200）、已屏蔽用户列表与解除。

## 4. 数据结构要点

```
弹幕 { id, video_id, user_id, content, time_ms(视频内时间),
       mode(滚动/顶/底), color, font_size, status, created_at }
屏蔽 { id, user_id, block_type(1关键词 2用户), keyword/block_hash, created_at }
```

- 存储：MySQL 持久化 + Redis 分段缓存（video_id + 分段号）；屏蔽表按 user_id 索引。
- 实时通道：**WebSocket 按视频房间广播**（`/api/v1/ws/danmaku?bvid=`），发送成功 → 推送同视频在线连接；HTTP 分段拉取保留作降级兜底。
- 屏蔽生效链路：渲染前过滤（服务端拉取接口不返回被屏蔽项 + 实时广播客户端本地过滤）。

## 5. 指标与边界

- 弹幕加载耗时 P90 < 200ms（缓存命中）。
- 单视频弹幕池上限（如 8000 条/6min 段），超出按权重淘汰展示。
- 视频被锁定时弹幕停止对外展示。
- WS 广播延迟 P95 < 500ms；单视频在线连接数上限（如 5000，超出部分回退拉取）。
