# PRD：内容审核与管理后台

> 优先级：`P0` ｜ 版本：MVP 起 ｜ 状态：草案

## 1. 需求背景

UGC 平台合规底线：“先审后播”。管理后台是内部效率工具，覆盖内容审核、用户治理、运营配置、数据大盘、权限与系统管理五大职能，需完整的 RBAC 权限体系与操作审计。

## 2. 审核体系

### 2.1 审核对象与策略

| 内容类型 | 机审 | 人审 | 时效目标 |
| --- | --- | --- | --- |
| 视频稿件 | 抽帧图审 + 音频转文本 + 标题/简介/封面文审 | MVP 全量人审；V1 起机审低风险抽检、高风险全人审 | < 2h（高峰 < 6h） |

| 头像/昵称/签名 | 机审 | 举报触发 | < 4h |

## 6. 权限与账号体系（RBAC）

采用标准 **RBAC**（用户-角色-权限三层）：管理员账号绑定一到多个角色，角色聚合权限点，权限点控制菜单可见性与操作按钮。超级管理员拥有全部权限且可管理角色/权限。

### 6.1 数据模型

| 表 | 说明 | 关键字段 |
| --- | --- | --- |
| `admin_user` | 管理员账号 | id, username, password(bcrypt), nickname, status(0正常/1停用), last_login_at |
| `admin_role` | 角色 | id, code(唯一), name, remark, is_builtin(内置角色不可删) |
| `admin_permission` | 权限点/菜单 | id, code(如 `content:review`), name, type(menu/button/api), parent_id(菜单树), path |
| `admin_user_role` | 账号-角色关联 | admin_user_id, role_id |
| `admin_role_permission` | 角色-权限关联 | role_id, permission_id |

> 权限点 code 采用 `模块:操作` 命名（如 `user:ban`、`role:edit`、`sensitive:delete`），后端中间件与前端指令统一按 code 校验。

### 6.2 管理员账号管理（ADMU）

| 编号 | 功能 | 说明 | 优先级 |
| --- | --- | --- | --- |
| ADMU-01 | 账号列表 | 分页 + 按用户名/状态/角色筛选 | P0 |
| ADMU-02 | 新建/编辑账号 | 设置用户名、昵称、初始密码、绑定角色（多选） | P0 |
| ADMU-03 | 启用/停用 | 停用后立即令其令牌失效、禁止登录 | P0 |
| ADMU-04 | 重置密码 | 管理员重置他人密码；本人改密 | P1 |
| ADMU-05 | 登录记录 | 最近登录时间/IP，异常登录提示 | P2 |

| 编号 | 功能 | 说明 | 优先级 |
| --- | --- | --- | --- |
| PERM-01 | 权限点/菜单树 | 树形维护菜单与操作按钮权限点 | P1 |

### 6.5 预设角色与权限矩阵

| 角色 | code | 权限范围 |
| --- | --- | --- |
| 超级管理员 | `super` | 全部 + 账号/角色/权限管理 |
| 审核主管 | `review_lead` | 审核 + 复审 + 审核数据 + 敏感词库 |
| 审核员 | `reviewer` | 认领队列审核 |
| 运营 | `operator` | 运营配置（分区/Banner/热搜/公告）+ 数据大盘只读 |
| 用户治理 | `moderator` | 用户查询/处罚/申诉复核 |
| 数据分析 | `analyst` | 数据大盘只读 |

> 内置角色随系统初始化创建；`super` 不可编辑权限（恒为全集）、不可删除。

### 6.6 安全与审计

- 所有写操作二次确认 + 审计日志（操作者/时间/对象/动作/前后值/IP）。
- 后台独立域名 + IP 白名单 + 强制 2FA（V1）。
- 令牌与 C 端完全隔离（jwtx Admin claim），停用账号即时失效。
